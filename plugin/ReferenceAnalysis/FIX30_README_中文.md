# 琉璃 · WeChat Liquid Glass · TEST4 FIX30

版本 `0.4.30-test4fix30`，基于 FIX29。改动在 `WXGGlassView.m`、`WXGHost.m`、`WXGSettings.m`、`WXGIntegration.h` 和 Makefile；`WXGOpticalSettings.m` 已并入新设置并删除。其余 25 个源文件与 FIX29 逐字节相同（`tools/audit_fix30_scope.py`）。

## 底栏切换卡顿：是 FIX27/28 引入的回退

你之前导出的切换记录：

| | 微信自身切换耗时 | 切换后最长一帧 |
| --- | --- | --- |
| FIX26 | 0.5–3 ms（一次 31 ms） | 大多 17–70 ms |
| FIX27/28 | 24–56 ms（一次 218 ms） | 110–300 ms（一次 508 ms） |

微信本身没有变慢。变化在于：FIX27/28 为了消除“闪一帧”，让玻璃在**每次布局和激活时同步画一帧并等 GPU**。切换标签会让新页面所有玻璃都布局、激活一遍；底栏玻璃在透镜动画的每一帧都会布局。于是每块玻璃都在微信的切换过程里多了一次“绘制 + 等待”，底栏在动画中每帧画两次。

FIX30：
- 布局和激活时不再同步绘制。新玻璃只在第一次时立即挂好背景层（保证不空一帧），绘制交回每帧的刷新。真正解决闪烁的两项（同步模式不显示占位色、菜单图片守卫）保留。
- **网格共享**：尺寸和参数相同的玻璃（例如所有页面的导航按钮）共用同一套网格，新页面的按钮不再各自重建 3–6 套网格。
- **标签页预载**：首次切换的大头是微信第一次创建这个标签页（那次 218 ms）。现在启动约 3 秒后、没有动画时，逐个（间隔 0.4 秒）在屏幕外加载并布局还没加载过的标签首页。真正切换时的 viewWillAppear 等仍按原样执行。
- 切换时的路由阶段拆成更细的计时（`runtime.tabSwitches[].refresh.routeSteps`）；装饰检查先按类名过滤，不再对新页面的每个视图（最多 900 个）都调用一遍。

请正常切换几次（包括冷启动后的第一次），然后导出诊断：`wechatSwitchMS` 应回到个位数毫秒，`prewarmedTabPages` 记录预载了哪些页面、各用多久，`meshCacheHits` 是复用网格的次数。

## 背景清理会不会太暴力、有没有额外开销

规则本身是精确的，不是按颜色或位置猜：
- 页面顶部：只清理贴着顶部、全宽、高度与导航区相同的底色、毛玻璃或渐变图，以及导航区底边的细线；含按钮、标题、文字的视图一律跳过。
- 转场底栏：只处理贴着屏幕底边、高度与原生底栏相同的毛玻璃或快照、底栏顶边的细线；跳过真实底栏、我们自己的底栏和正在离开的页面。

开销方面，FIX29 的扫描会遍历整页（最多 700 个视图），转场时每帧最多再加几百个。FIX30 改为**只沿着到达目标区域（顶部导航区或底部底栏区）的分支往下走**，不进入列表单元格，页面主体内容根本不会被访问；转场扫描找到目标后降为每三帧一次。清理状态都记录在可恢复的状态袋里，路由切换或关闭功能时能原样还原。

## 新设置：琉璃

- 入口在**微信「我 → 设置」**里，作为单独一组、和其他选项同级的「琉璃」一行；点进去就像打开微信自己的设置页一样推入。用的是微信自己的表格管理接口（和其他微信插件同一种做法），不是覆盖层。
- 悬浮的 WG 按钮已隐藏；只有在这个微信版本找不到设置表格接口时才会出现。长按底栏也能打开设置，作为备用入口。
- 结构：首页是 6 个开关，加 6 个分类入口（玻璃、按压透镜、边框、材质遮盖、底栏、菜单与比例），以及诊断和恢复默认。每个分类一页，大约一屏。
- 成对的设置不再重复列两遍。边框页顶部切换「浅色模式 / 深色模式」，默认显示当前系统外观；材质遮盖页顶部切换「其余玻璃 / 底栏」。
- 滑杆标题在左、数值在右，带单位；颜色项显示色块和色值，点开是**系统调色盘**（含透明度），拖动时实时预览。

