# WeChat Liquid Glass · TEST4 FIX13

版本 `0.4.13-test4fix13`。基于 FIX12，针对底栏点击不提交、进入聊天跳转、冷启动导航背景和采样开销修改。保留 FIX12 的输入修复预算与防重入；不更改现有输入设计、TEST9 折射／模糊参数或透镜运动。

## 这次抓取确认了什么

三个分包属于同一次 WGP4.3 抓取，共 223 条事件，序号 1–223 连续。插件为 FIX12，iOS 15.7／微信 8.0.73，屏幕最高 60Hz。抓取没有硬件型号，不能由尺寸推定机型。

- 五次底栏点击确实命中我们的底栏，预览位置也改变，但未看到切换提交；松手后约 350–400 毫秒才回到原位。这不是点击坐标完全没命中。原生 MMTabBar 有祖先手势识别器，取消／延迟控件触摸是待验证的具体原因，旧抓取未记录取消回调，不能当作已经证实。
- 进入聊天的原生调用带着 `animated=true`，全局动画也开启；然而页面很早到达终点。第一次进入时刷新耗时最高约 182 毫秒，第二次约 110 毫秒。同步刷新挤占原生导航过程有代码与耗时依据，尚不能保证它是全部原因。
- 按观察时间和真正的 Metal 呈现计数计算：首页稳定片段约 40–43 帧／秒，聊天片段约 25.5 帧／秒；这份设备抓取没有 120 帧。首页场景读取中位约 17.5 毫秒，聊天约 32.1 毫秒，转场最高约 90.8 毫秒。GPU 和缓冲池忙碌跳过均为零，主要瓶颈在主线程读取原生场景。
- 没有捕获冷启动白底的完整背景子树，因此白底具体归属仍不完全确定；不会据此把整个聊天／首页根背景清空。

## 修改内容

1. 底栏保留在原生 MMTabBar 中，继续跟随宿主移动。仅对命中我们的底栏及其子视图的触摸，阻止同一原生底栏上的手势识别器抢走事件；其他触摸转交原委托。关闭底栏替换或更换原生底栏时恢复委托，不覆盖其他插件新设的不同委托。结束触摸可以使用当前手势保存的位置，但必须确认结束事件；取消、离屏和非活跃状态不提交。原生 tab 选择调用未改变。
2. 页面准备、首次布局和 push/pop 退出时改为合并调度刷新，避免在原生导航调用堆栈内同步重建和准备纹理。原生 coordinator、可逆返回、坐标跟随和完成／取消处理保留；没有用自造动画替代原生转场。
3. 对当前 MMUINavigationBar 的 `_UIBarBackground` 绘制容器施加遮罩，允许早期布局时生效，同时保留其内部效果视图。只处理导航绘制层，不清除消息、置顶内容和整页根背景。补充白底相关限量状态记录，以便仍有残留时找准所属视图。
4. 场景仍来自当前页面组合。每轮只绘制所有玻璃完整 GPU 画布所需的多个区域，加上采样边界余量，跳过不相交分支；同一轮固定坐标映射，发布纹理时记录有效区域，失败时不发布半张图。键盘和返回过程中新露出的区域必须先有有效采样才能使用。画布大小、GPU 拷贝、完整分辨率高斯模糊和更新频率策略不变。

抓取中所需区域面积合计约为旧整幅采样的两成，这是几何面积对比，**不等于已测得五倍提速**。UIKit 可能仍为某些分支处理整棵原生子树，实际收益要看设备上的新耗时。

## 验证与安装

已完成 27 个 C 数值／策略测试；新增区域覆盖测试独立检查仿射变换、旋转、反射、画布出界钳制下每个像素的双线性采样点，并验证区域并集、空洞和键盘移动。触摸策略测试覆盖结束、取消、越界和无效坐标。源码范围审计确认 32 个文件、29 个关键方法与 FIX12 相同。

14 个 Objective-C 文件 × arm64／arm64e 通过真实 iOS SDK 语义检查；实际交付 arm64 iOS 13+ dylib，完成编译、链接与 ad hoc 签名。Metal 源码沿用设备首次使用时编译，未执行离线 GPU 编译。本环境无法运行微信／UIKit；这些检查不是对真机动画、触摸或帧率的验收。

替换旧主插件，保留原参数，完全退出微信再开，确认版本 FIX13。先不运行探针：

1. 冷启动等待数秒，查看顶部背景，再依次点通讯录、发现、我。
2. 进入聊天，再进入聊天设置并返回，比较两次原生转场；随后滑动返回首页。
3. 在聊天输入首行并收起键盘，查看玻璃是否持续更新，同时确认 FIX12 恢复的聊天可进入状态。

如仍有异常，只需用现有 WGP4.3 抓一段包含异常操作的短记录，不用重走全部流程。探针通过既有采样接口读取新增字段，不需要换探针版本。系统结束微信时保留新的 `.ips`。

## 新增诊断

`host.sampling` 增加 `dockInteraction`（开始／结束／取消／提交及原因）、`dockGestureProtection`（当前识别器和包装状态）、`navigationChrome`（每半秒最多 16 条导航背景状态）。`backdrop.regions` 增加有效区域、强制补采／拒绝过期区域、裁剪分支，以及填充／原生场景读取／上传分段耗时和六条最慢分支。

不增加自动截图或逐帧写文件，旧探针已有的分包行为保持不变。诊断和范围报告见 `Validation/`；带旧版本名称的文档仅用于历史追溯。

自行编译：设置 `THEOS` 后运行 `./build.sh rootless` 或 `./build.sh rootful`。安装包里附有对应的完整源码 ZIP。
