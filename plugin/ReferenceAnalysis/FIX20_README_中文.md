# WeChat Liquid Glass · TEST4 FIX20

版本 `0.4.20-test4fix20`，基于 FIX19。默认路径（回读 + 模型树·FIX4 + 与界面同帧提交）与 FIX19 完全相同：`WXGBackdrop.m`、着色器、TEST9 光学等 24 个源文件逐字节未改（`tools/audit_fix20_scope.py`）。本版只升级“同步”渲染方式。

## 你上传的两个插件是怎么做的

两者都没有 Metal、没有显示回调、没有任何背景回读，全部交给系统渲染服务在上屏那一刻计算，所以没有延迟。

- **微信液态玻璃58（wcliquidglass）**：核心是 `CCLiquidGlassView`，内部是系统模糊视图或手动的 `CABackdropLayer`、色调层、渐变层、描边，再加一个**网格变形（mesh transform）**做折射（设置里有“折射强度”，属性里有 `cachedMeshRefractionStrength`）。所以它不是只有模糊，而是有折射的，只是强度小、没有 RGB 色散、没有逐像素光学，看上去就像普通毛玻璃。它把私有类名和键名藏在运行时解码的字符串里。
- **Liquidify**：SpringBoard 插件，作用于控制中心、文件夹、小组件、灵动岛、锁屏时钟等，钩的是 SpringBoard 的类，放进微信不会起作用。方法和上面一样：`CABackdropLayer`，加 `gaussianBlur`（含边缘归一化）、`colorSaturate`/亮度/对比度、带 `inputBackdropAware` 的颜色矩阵，再用网格变形和细分步数做“标签边缘折射”。两者出自同一套 CC 液态玻璃代码。

## FIX19 到瓶颈了吗

基本到了。读模型树、提交前读取、和界面同帧上屏之后，回读这条路线剩下的只有一件事：**每帧在主线程上用 CPU 把玻璃下面那块画一遍**。开启同帧提交后，这一步直接排在微信这一帧提交之前，读得越勤，越跟手，也越容易掉帧——这就是你感到“有点延迟”（读取被预算推迟）和“有点掉帧”（读取挤占了这一帧）的来源。再往下只能靠降低读取分辨率换时间，不会有质的变化。

建议先确认设置没有被之前的试验改动：

| 项 | 建议 |
| --- | --- |
| 渲染方式 | 回读（如果之前切到混合/同步，设置会一直保留） |
| 采样来源 | 模型树·FIX4 |
| 与界面同帧提交 | 开；如果掉帧明显，关掉对比 |
| 主线程占用上限 | 120Hz 机型可试 50–60；越高越跟手、越容易掉帧 |
| 显示时刻预测 | 开（只在系统动画期间起作用） |

诊断里 `backdrop.regions[].costAverageMS`（每次读取耗时）、`budgetHolds`（被预算推迟的次数）、`measuredMainThreadShare` 能直接看出是哪一种。

## FIX20：真正零延迟的“同步”方式，加上 TEST9 折射

真正没有延迟只能走渲染服务，就像那两个插件。FIX18 的“同步”缺的正是折射，这一版补上：

- **网格折射**：用和着色器**完全相同**的形状场（`WXGRoundedOpticalField` / `WXGCapsuleOpticalField`）和折射曲线（`WXGOpticalOffset`）在 CPU 上生成网格，交给 `CABackdropLayer` 的网格变形，由渲染服务在上屏时弯折实时背景。网格在边缘带密、内部疏；与逐像素 TEST9 的偏差：导航按钮、输入胶囊约 0.27pt，底栏约 0.5pt，透镜放大 1.2 时约 0.5pt（`Tests/MeshRefractionTests.c`）。不做网格细分平滑，避免把折射曲线磨平。
- **清晰折射边**：TEST9 默认“模糊覆盖扩展 0%”时，边缘一圈是不模糊的折射。这里用第二个不模糊的背景层（与主体同一组捕获），套同一个网格，再用与着色器完全相同的 `WXGBlurSharpWeight` 生成遮罩，只露出那一圈。
- **透镜**：按压底栏时，透镜背景按 TEST9 的透镜折射和放大倍数（默认 1.2）生成网格，每帧随按压更新。
- **饱和度**：补上 TEST9 的 5% 饱和度增强。
- 材质遮盖、线框、选中胶囊、图标仍由原着色器叠加。主线程不读背景，只有几何变化时重建网格（几百个顶点）。

**仍然缺的**：RGB 色散。网格只能整体移动像素，不能把三个颜色通道分开；这是渲染服务方案和回读方案唯一的光学差别。

切换：设置 → 采样 → 渲染方式选“同步”，“同步模式网格折射”默认开，可关掉对比。

## 安装

```bash
cd /var/mobile && unzip -o WeChatLiquidGlass_0_4_20_TEST4_FIX20_flat.zip -d WeChatLiquidGlass_FIX20 && cd WeChatLiquidGlass_FIX20 && chmod +x build.sh && ./build.sh rootless
```

rootful 环境把最后的参数换成 `rootful`。完全退出再打开微信，确认设置标题为 FIX20。

## 这轮请对照

1. 渲染方式“回读”与“同步”，在带壁纸的聊天里快速滚动、进出设置：同步应完全没有拖影；比较两者的折射边缘观感，以及色散缺失是否明显。
2. 同步模式下按住底栏拖动透镜：放大与边缘弯折是否跟手。
3. 关闭“同步模式网格折射”对比一次，确认网格确实生效。

诊断（每块玻璃 `materialLayers`）：`meshTransformClass`、`bodyMeshAccepted`、`bodyMeshVertices`、`lensMeshAccepted`、`edgeRingLive`。

## 已知风险

- 网格变形是私有接口。我按 QuartzCore 的顶点和面结构调用；如果系统内部布局不同，同步模式里的玻璃内容会错乱或空白。出现这种情况关掉“同步模式网格折射”即可，并请导出诊断。CC 插件在某些系统上也会遇到背景层拒绝网格（它们会打日志），本版在 `bodyMeshAccepted` 里记录。
- 同步模式看到的是玻璃下面屏幕上实际存在的所有内容；没有被插件清掉的原生背景会出现在玻璃里。
