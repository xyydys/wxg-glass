# WeChat Liquid Glass · TEST4 FIX21

版本 `0.4.21-test4fix21`，基于 FIX20，针对你这轮反馈和上传的诊断（iPhone XS Max 级 A12，60Hz，iOS 15.7）。

## 诊断里看到的

- **列表掉帧的直接原因**：主线程占用上限被设成了 80%，导出时背景读取实际占了主线程的 **67%**，每次读取约 12.5ms（一帧只有 16.7ms）。读取这么贵，是因为首页靠近底栏的两个会话单元格（`NewMainFrameCell`）里有带滤镜的图层：每次读取都因此离开便宜的模型树路径（2297 次），每个这样的单元格再走约 3ms 的系统合成读取。
- 一次提交前处理耗时 496ms（`maxCostMS`），这次包含了微信首次创建新标签页时的布局（在我们的布局调用里发生），以及首次读取新页面。

## 本版修改

1. **读取变便宜（列表掉帧）**：颜色滤镜、混合模式的图层改为直接绘制（不带滤镜，在模糊的玻璃下几乎看不出差别），不再强制走系统合成。只有会采样屏幕的背景滤镜仍走系统合成。首页应恢复为模型树读取，`compositorFallbacks` 应接近 0。**主线程占用上限请调回 35–50。**
2. **键盘升起时的灰色**：键盘升起会改变输入栏高度（底部安全区被去掉），玻璃尺寸变化后要等一张新背景才显示。动画期间读取被“新动画保护”、预算和覆盖检查推迟，于是露出下面的灰色好几帧。现在：没有画面的玻璃会立即强制读取（不受预算和新动画保护限制，最多连续 12 次），应只剩一帧以内。
3. **首次切换底栏卡顿**：底栏图标是两张整条底栏大小的纹理（约 1489×489），每次发现新的标签图标都在主线程重画并上传。现在第一次之后都在后台线程绘制和上传，完成前继续显示旧纹理，不再卡住切换。微信自己第一次创建标签页的耗时仍然存在。
4. **强调色延迟跟随**：微信只有在某个标签被选中后才显示它的绿色图标，有时还有一段自己的图标动画；之前要等约 0.8 秒的采样间隔。现在切换后在 0.12、0.35、0.75 秒各补扫一次，新的切换会取消旧的补扫。
5. **透镜里图标反向微动**：LUMI 运动拉伸透镜时透镜中心会移动，而图标按透镜中心映射，所以向反方向抖。现在图标以它在底栏里的锚点为中心放大，透镜形状怎么变都不会带动图标。
6. **iOS 26 式透镜边缘**（设置 → 透镜）：
   - “透镜折射宽度 · pt（两端）”：两端的折射范围，就是原来的宽度。
   - “透镜上下折射宽度比例”：透镜伸出底栏上下那部分的折射宽度，相对两端的比例。**1 = 和以前完全一样**；想要上下变成细边，试 0.25–0.4。
   - “上下收窄曲线”：离开两端时收窄得多快。默认 3：刚离开两端收得快，接近上下时变慢，就是你描述的“先快后慢”。例：两端 12pt、比例 0.3、曲线 3 → 30° 处 9.1pt，60° 处 4.6pt，上下 3.6pt。
   - 色散只在折射带内出现，所以上下会自然变成一道细彩边。
7. **透镜里偏白、外面是灰**：读不到任何视图的地方，以前一律填白色；屏幕上那里实际显示的是更底层（常常是窗口）的背景色。现在沿父视图向上找第一个不透明背景色来填，诊断里 `baseFill` 记录用的颜色。上下折射变窄后，透镜也不会再从那么远处取色。
8. **冷启动顶部白底 / 视频号返回残留背景**：导航栏背景清理以前只在路由变化时做；微信之后再画或新增的背景视图要等下次跳转才被清掉。现在每秒复查一次导航栏自身，并在每次转场**开始**时清理目标导航栏背景。

## 这轮请对照，并在有问题时导出诊断

1. 首页快速滚动：`backdrop.regions[].lastPath` 应主要是 `modelTree`，`costAverageMS` 应明显低于 12，`compositorFallbacks` 不再增长。
2. 聊天页收放键盘：输入栏玻璃是否还变灰；`forcedFrameReads` 会记录强制读取次数。
3. 冷启动后**不要操作**，直接导出一次诊断（如果顶部还是白的）；视频号返回时如仍有残留，返回途中截图。`runtime.navigationPaintRescans` 记录复查次数。
4. 透镜：比例 0.3、曲线 3 下看伸出部分是否收成细边；透镜里颜色是否和外面一致（`baseFill`）。

## 已知限制

- “同步”渲染方式的透镜网格仍是各向同性的（新比例只作用于回读和混合）。
- 透镜与底栏上下边交界处的过渡没有改；先看上下变细后观感如何。
- 本环境无法编译 Objective-C 和 Metal，请以手机端 `./build.sh` 为准。已完成：37 个 C 测试（新增透镜边缘宽度测试）、全部源文件和着色器括号结构检查、FIX20→FIX21 范围审计（19 个文件未改动）。
