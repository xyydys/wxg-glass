# WeChat Liquid Glass · TEST4 FIX44

版本 `0.4.44-test4fix44`，基于 FIX43。18 个源文件与 FIX43 逐字节相同（`tools/audit_fix44_scope.py`）。切换的速度和时长、拖动手感、冷启动修复都不变。

## 透镜里的底栏也参与折射和色散

之前同步模式下，透镜那一遍在**真实位置**画底栏的材质、轮廓和描边，所以透镜下面的底栏始终完整、笔直，只有图标和文字被折射。iOS 26 是把底栏自己的上下边缘也一起折射、色散。

现在透镜内底栏的轮廓、材质和描边都按透镜的映射取样（与透镜毛玻璃同一条折射曲线和放大），红绿蓝三个通道分别取样，所以底栏边缘在透镜的边沿处会弯曲并带彩边。静止时映射是恒等的（无偏移、放大为 1），静止胶囊完全不变。

## 掉帧

不是时长按比例放大和刷新率不匹配造成的：Core Animation 的动画按时间计算，每一帧单独取样。代码里找到的是这几处负担：

1. **透镜下的“洞”是一条每帧都在变的路径遮罩**（4000pt 的偶奇路径，每帧都要重新细分，再离屏合成），在 A12 上很贵。现在改成一张预先画好的透明度图片，只动它的位置和尺寸，不再每帧重新细分路径。
2. **透镜里的图标用了第二个动画遮罩**。现在图标直接放在透镜图层里，由透镜本身裁剪，少一次离屏合成。
3. **被隐藏的 Metal 叠加层在动画期间仍每帧绘制**，白白占用 GPU。现在隐藏时不画，动画结束交接前那一帧照常画。
4. **按下后的滑动还在主线程上**，只有松手后的部分在渲染服务里。刚启动、或刚切换完页面时微信占着主线程，每次点按的前约 100 ms 就会卡一下，这和你说的刚启动切换有一点点延迟对得上。现在按下另一个标签时，滑动和浮起也交给渲染服务：透镜浮起到 90%，滑到目标后保持浮起；松手就落成胶囊，落地时间仍按原计划（距松手至少 0.1 秒）。如果滑动途中开始拖动，就从透镜此刻在屏幕上的位置和大小，无缝交给逐帧的跟手透镜；在别处松手也一样交回。
5. **第一次使用**：动画图层在启动后空闲时就已建好，但渲染服务要到第一次点按才第一次绘制它们。现在预热时会以 0.001 的不透明度把它们画一次，让渲染服务提前准备好。

## 诊断

`dockInteraction` 新增 `glides`（按下滑动次数）、`drops`（松手落下次数）、`handovers`（拖动交接次数）、`glideCancels`（交回次数）、`travelSetupMaxMS`（动画准备的最长耗时）。逐帧归因（`dockProfile`）仍然有效：如果还有掉帧，它会显示是主线程上谁占了时间；如果主线程空闲而仍然掉帧，就是渲染服务那边的负担。

