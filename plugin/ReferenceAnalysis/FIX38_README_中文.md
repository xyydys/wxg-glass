## 冷启动：上次为什么“没变化”

两处都是我的错，修复都没有真正生效：

1. **图标缓存被第一次读取覆盖**。缓存是在创建时载入的，但启动后第一次读取（微信的图标还没准备好，读到 0/4）被当成“新数据”，整组替换掉了缓存，于是还是内置符号。现在每次读取只替换真正读到的部分，没读到的位置保留缓存或上一次读到的图标；底栏还不足四项时也不再清空。主题插件换图标时，新图标是真实读取，仍然会替换缓存。
2. **顶部按钮的玻璃总是晚一拍**。页面出现（`viewWillAppear`）时会被标记为“待出现”，而这个标记只在导航转场结束时清除。切换标签和冷启动时首页出现都没有转场，于是这个标记一直留着：之后每一次原生导航布局都被推迟到下一轮刷新，总比微信自己的按钮晚一帧以上（你的诊断里推迟了 328 次，回首页时绑定修复 49 次）。现在只有真正带转场的出现才标记，每次刷新时若没有转场在进行就清除残留标记；导航玻璃能在微信布局按钮的同一次提交里建好。

冷启动日志也补充了：每次导航构建找到了哪些原生按钮、每次推迟的原因（导航调用中 / 页面待出现 / 转场中）、每次绑定修复的原因（按钮被替换 / 按钮离开窗口）。相同的行会合并成一行并计数。诊断新增 `appearances`、`stalePendingClears`。
