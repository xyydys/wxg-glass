# WeChat Liquid Glass · TEST4 FIX34

版本 `0.4.34-test4fix34`，基于 FIX33。21 个源文件与 FIX33 逐字节相同（`tools/audit_fix34_scope.py`）。

## 页面比底栏慢

录屏逐帧测量：底栏到达新标签后，微信页面分别晚了 0.12、0.48、0.17 秒。原因有两个：
- 你之前测试时选的「到位」时机还在生效，要多等一次刷新；
- 微信切换页面本身用了 28–217 ms。

现在底栏动画由系统渲染，主线程卡不到它，所以只要是新动画的点击，都会**立即**把切换交给微信，不再看「切换时机」设置。剩下的就是微信自己切换页面的时间，这部分我们改变不了。

## 图标重影、错位

你第二张截图里，绿色指南针外面那圈黑边，是微信**未选中**状态的图标（黑色线框）。FIX33 的动画透镜把绿色的选中图标画在底栏的未选中图标**上面**，而微信的选中、未选中图标形状不同，于是两个同时露出来，看着像重影和错位。另外，动画开始时底栏要立即画一帧“无胶囊”的画面；如果上一帧还在 GPU 上，这一帧会被跳过，旧胶囊就留在原处，新旧状态同时出现。

现在：
- 透镜内部改为不透明，用底栏的实际颜色（底栏材质叠在微信页面底色上），浮起时略提亮；落下后的胶囊是选中色叠在同一底色上。透镜下面只看得到绿色的选中图标，和 iOS 一样。
- 去掉了透镜里的毛玻璃层：它会把底栏自己的黑色图标也采进来、模糊地露在透镜下面。
- “无胶囊”那一帧会等 GPU 空出来（最多 12 ms），不再跳过；诊断 `neutralFrameMisses` 记录仍然没画成的次数，应为 0。
- 动画结束时，动画透镜在真实胶囊上方用 0.12 秒淡出（两者绿色图标位置、大小完全一致），而不是一帧之内硬切换。

## 冷启动：图标被模糊挡住

FIX33 让玻璃在着色器就绪前就显示毛玻璃，但底栏的备用图标和备用透镜在玻璃下面，被它的模糊盖住了。现在两者移到玻璃上方；等真正的叠加层画出第一帧，它们就隐藏。叠加层仍然要等着色器编译完成才出现，这一点没变。
