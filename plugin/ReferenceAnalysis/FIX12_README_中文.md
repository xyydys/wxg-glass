# WeChat Liquid Glass · TEST4 FIX12

版本 `0.4.12-test4fix12`。仅针对 iOS 15.7 进入聊天后卡死的输入栏布局路径修复；基于 FIX11，原工程与安装包保留。

## 系统报告确认了什么

`WeChat-2026-10-04-201646.ips` 中的插件 UUID 与已交付 FIX11 二进制完全一致。设备为 iPhone11,6（XS Max），iOS 15.7，微信 8.0.73。

系统因 `scene-update watchdog` 的 10 秒超时结束进程（FRONTBOARD `0x8BADF00D` / SIGKILL）。主线程采样栈：

```
原生输入视图 layoutSubviews hook
→ WXGIntegrationHost layoutInput
→ WXGInputAdapter layout
→ WXGStateBag reapply
→ NSMapTable 弱引用枚举
```

报告证明超时现场位于这条输入适配路径；单份栈不能证明枚举器死锁。内核同时记录了内存资源不足，但这不是可直接归因于插件的泄漏证明，虚拟内存总量也不是常驻内存。

## 本次修复

1. 两端输入栏不再反复调整按钮顺序。FIX11 每轮先将语音按钮移到最上层，再将表情按钮移到最上层；即使最终顺序没有变化，每轮仍产生两次层级写入。现在先核对最终顺序，正确时不写入。
2. 输入栏同步修复每个显示回调间隔最多执行四次，超出的请求合并为一个 pending 标志，下一显示回调在背景采样之前处理最新状态。预算只由真实显示回调重置；循环拖得再久也不能靠时间重新获得预算。首次安装仍即时布置，普通布局不必等待下一帧。
3. 退到后台／失去活跃状态时停止输入修复，包括 WillResignActive 已触发、UIApplication 状态尚未更新的短窗口。保留已有视图和纹理，回到前台再处理。
4. 背景状态重应用增加防重入，同一轮持有一个短期视图引用；重复隐藏可访问性内容时不再写相同值。离场输入栏的背景修复也纳入保护。

改动没有关闭输入栏，也没有给玻璃降帧。背景采样、GPU 拷贝、TEST9 材质／折射／模糊、透镜动画、三端输入实现、输入几何与动作、顶栏和底栏挂载实现与 FIX11 保持一致。两端输入布局内部只调整按钮层级顺序。**这不是对实际帧率或低设备所有卡顿都已解决的保证。**

## 验证与安装

已执行 25 个 C 数值／策略测试，含稳定按钮顺序、缺失／替换表情按钮、十万次重复回调、重入、延后处理最新状态、60/120 Hz 显示周期。改动范围审计核对 33 个源码文件和 16 个方法与 FIX11 一致。13 个 Objective-C 文件完成 arm64、arm64e 检查；实际编译、链接、签名的是 arm64 iOS 13+ dylib。编译包含 dylib、plist、rootful/rootless deb 和同版完整源码。

本环境不能运行微信/UIKit，系统 watchdog 尚未在真机复现和回归验证。数值测试证明策略有界与顺序稳定，不等于已证明设备不会再卡死。Metal 编译方式沿用 FIX11，在设备运行时完成。

替换旧主插件后完全退出微信再开，保留原参数，确认版本为 FIX12。先不用探针，只做一次“首页进入聊天”；能进入后再验证输入首行、表情／语音切换和退到后台再回来。无需重跑整套流程。如仍被系统结束，新的同类 `.ips` 就能用于核对版本和主线程现场，不必在卡死时强行操作探针。

## 新增轻量指标

现有 WGP4.3 可在 `host.sampling.inputRepair` 读取：

- `requests / passes / deferred`：修复请求、实际处理、合并延后次数。
- `usedThisFrame / budget / pending`：当前显示间隔用量、上限、是否有待处理请求。
- `inactiveSkips`：非活跃期间忽略的请求数。
- `lastMS / maxMS`：输入修复的 CPU 耗时。

指标只有计数，不新增逐帧截图或日志写入。旧采样指标仍保留。

自行编译：`export THEOS=/opt/theos` 后运行 `./build.sh rootless` 或 `./build.sh rootful`。本版检查见 `VALIDATION.md`；旧版命名报告和审计工具仅作历史追溯。
