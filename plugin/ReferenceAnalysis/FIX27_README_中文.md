# WeChat Liquid Glass · TEST4 FIX27

版本 `0.4.27-test4fix27`，基于 FIX26。网格生成器、几何、输入、底栏交互等 18 个源文件与 FIX26 逐字节相同（`tools/audit_fix27_scope.py`）。

## 只保留同步模式

- 渲染方式固定为同步，折射网格始终开启。设置里的回读、混合、采样来源、同帧提交、采样帧率、主线程上限、显示时刻预测全部删除。
- 同步模式下不再运行任何背景读取流程：没有排队帧、没有提交前布局、没有延迟绘制，每帧只更新几何并画叠加层。
- “采样倍率”：0 表示跟随屏幕，你的设备是 3 倍屏，所以 0 和 3 完全相同，你看不出差别是正常的。调低能减轻 GPU 负担，但画面会变糊。
- 背景层挂在每块玻璃自己的裁剪视图里（与玻璃同形状、同圆角），这是效果最好的一层；没有改动。

## 滑动聊天掉帧

诊断显示主线程很轻（每帧约 0.8ms），所以掉帧主要来自渲染服务的 GPU 负担，高刷屏的每帧预算更短，所以更明显。本版减负：
- 去掉上面说的每帧读取流程；
- 色散三层背景，每层把“5% 饱和度”和“通道分离”合并成一次颜色矩阵，少一遍滤镜；
- 模糊半径小于 0.2pt 时不加模糊滤镜（看不出来，但会多一遍处理）；
- 给背景层加采样边距，模糊边缘取到真实内容。你说过一次的“静置胶囊某个方向极细的黑边”很可能就是边缘取样不足造成的。

如果仍然掉帧，可以先试：关 RGB 色散（三层变一层）、把模糊覆盖扩展设为 100%（去掉清晰折射边那三层）、或者把采样倍率调到 2。

## 转场与冷启动残留

- **冷启动顶部白底**（深色为暗底）：上一版的冷启动统计查到了来源：首页 `MainFrameTableView` 里一个铺满全屏、不透明的普通 `UIView`，微信大约 10 秒后或一滑动就会移除它。现在发现后直接清掉它的底色，它后面就是正常的灰色页面。
- **聊天返回首页 / 视频号返回时的原底栏和白底**：原生底栏本身一直被遮罩，看到的是微信为转场截取的底栏快照（截图不带我们的遮罩，所以有旧图标和白色背景）。现在转场开始时，会在标签首页和转场容器里找出贴着屏幕底边、高度与原生底栏一致的快照视图并隐藏；下次路由切换时自动恢复。
- **下拉首页回弹后加号闪一下 / 打开加号菜单闪一次黑底**：新建或尺寸变化的玻璃以前要等 GPU 回报后才显示，并且要到下一帧才挂上背景层，中间会空一帧。同步模式下现在在同一次布局里就挂好背景层、画好叠加层并立即显示。
- **聊天设置页顶部背景、朋友圈下拉后顶部背景**：这两处还没有数据，这版加了专项抓取。进入任何非标签页 0.4 秒后记录顶部；页面第一次下拉超过 40pt 时也记录一次；回到标签首页时额外记录底部（看视频号返回时底栏下面是什么）。请复现后导出诊断，看 `runtime.coldStartTopPaint`，标签为 `settled:…`、`pullDown:…`、`transitionToTabRoot+0.12s`。

## 设置调整

- **透镜形变**：弹性形变始终开启，设置项删除；代码里所有带 “lumi” 的名字都改掉了（包括 luminance → toneLevel），审计脚本确认源码、测试和工具里一处都没有。
- **边框 · 浅色 / 深色**（两个分区）：底栏边框颜色、不透明度、宽度；透镜边框颜色、不透明度、宽度；边框亮度（1 为原色，低于 1 变暗，高于 1 向白色混合）；左下/右上渐隐；**左上渐隐、右下渐隐**（新，分别作用于上边+左边、下边+右边）。首次运行沿用你之前的线框设置（深色的不透明度 = 原不透明度 × 原深色亮度）。
- **材质遮盖 · 其余玻璃** 和 **材质遮盖 · 底栏**：分别设置底色和深浅色遮盖程度；都新增“减弱范围”（从轮廓起多宽开始减弱，0 = 与折射宽度相同）。底栏首次沿用之前的通用值。
- **消息长按菜单圆角**：默认 18。若微信菜单容器本身裁剪了更小的圆角，以较小者为准。
