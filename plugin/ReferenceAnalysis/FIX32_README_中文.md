# WeChat Liquid Glass · TEST4 FIX32

版本 `0.4.32-test4fix32`，基于 FIX30（含未单独发布的 FIX31）。22 个源文件与 FIX31 逐字节相同（`tools/audit_fix32_scope.py`）。

## 设置：恢复原有设置，只换入口

- 两个设置页恢复为 FIX29 的原样：普通玻璃和透镜的折射、色散、模糊依旧是各自独立的两组。
- 入口仍在微信「我 → 设置」里，单独一组，名字恢复为「微信 Liquid Glass」。悬浮按钮保持隐藏；长按底栏也能打开设置。
- 在原设置上只改了三处：
  1. 颜色项改用系统调色盘（你之前要求的），拖动时实时预览；
  2. 第一组新增「底栏切换页面」：松手 / 到位 / 落下（见下）；
  3. 从微信设置推入时不显示「完成」按钮（有返回），长按底栏弹出时才有。
- 编译错误（`___isPlatformVersionAtLeast`）的修复与你自己的改法相同：不再用 `@available`，改用 `NSProcessInfo` 判断系统版本。全部源码中已没有 `@available`。

## 底栏切换和动画卡顿

点一次底栏，主线程上有这些工作，而透镜动画也跑在主线程上，任何一项卡住，动画就停：

1. **松手那一刻，微信自己切换页面**：同步执行，1–56 ms；切到首页时稳定在 31–46 ms。
2. **紧接着，我们的路由刷新**：切到首页时即使在 FIX26 也要约 31 ms。
3. **按下和松开的每一帧**：透镜的大小、放大和折射随按压变化，每帧要为三个颜色通道各重建一套网格再提交。
4. **切换后 0.12 秒（正好在滑动当中）**：底栏重新读取微信图标；如果图标变了，会在主线程上传整张图标贴图。

这一版：
- **第 3 项去掉**：按压量按 1/32 取整，透镜尺寸按 0.5pt 取整（放大倍数每级差不到 0.7%），相邻帧共用同一套网格，算过的放进缓存，之后每次点击都不再重建。按钮按压同样处理。
- **第 4 项挪开**：图标复查改在动画结束后（0.45 秒和 0.9 秒）。
- **第 1、2 项可选择错开**：设置第一组「底栏切换页面」：
  - 松手（默认）：与系统一致；
  - 到位：透镜滑到目标后再切换，约晚 0.1 秒，滑动过程不受页面加载影响；
  - 落下：透镜完全落下后再切换，动画最流畅，页面出现最晚。
  等待期间底栏不会被同步回旧标签；超过 0.6 秒无论如何都会切换。
- FIX30 的修复保留：布局时不再同步绘制、相同玻璃共用网格、启动后预载标签页、清理只扫目标区域。
- **逐帧归因**：从按下底栏到切换后 1.5 秒，最慢的 16 帧记在 `runtime.dockProfile.worst`。每帧都有：主线程睡了多久（`idleMS`）；我们每帧刷新（`tickMS`，以及其中底栏 `dockMS`、叠加层 `drawMS`、背景层 `syncMS`、网格 `meshMS`/`meshBuilds`、清理 `cleanupMS`）；路由刷新 `refreshMS`；微信切换 `switchMS`；剩下的忙碌时间 `otherMS` 就是微信自己的工作。

## 请这样测

1. 默认「松手」：冷启动后先切一轮四个标签，再来回切几次；
2. 换成「到位」再试，比较手感；
3. 导出诊断发我。

看诊断就能定位：
- 如果最慢的帧主要是 `otherMS`，说明是微信自己的页面工作，「到位」或「落下」就是正解；
- 如果我们的某一项占大头，我就专门改那一项；
- 如果主线程空闲、帧间隔却仍然偏长，问题在渲染服务（GPU）一侧，下一步减少底栏的背景层数量。
