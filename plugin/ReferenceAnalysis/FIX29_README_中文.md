# WeChat Liquid Glass · TEST4 FIX29

版本 `0.4.29-test4fix29`，基于 FIX28。网格、几何、输入、底栏交互等 16 个源文件与 FIX28 逐字节相同（`tools/audit_fix29_scope.py`）。

## 聊天设置、服务、朋友圈等页面的顶部背景

上次的抓取其实已经说明了问题，我没有跟进，这次补上。几次抓取结论一致：这些页面的顶部背景不是导航栏画的，而是**页面自己**放的一块视图，紧贴顶部、全宽、高度正好等于导航区（0–88pt），所以导航栏清理从来碰不到它：
- 聊天设置（`ChatRoomInfoViewController`）：一块不透明的白色 `UIView`；
- 服务（`WCPayMainViewControllerV2`）：同样形状，不透明灰色；
- 朋友圈（`WCTimeLineViewController`）：一块毛玻璃 `UIVisualEffectView`，88pt 处还有一条细分隔线，顶部另有一层 120pt 的渐变图。
- 群聊列表等页面：88pt 处的细分隔线。

现在对每个页面都清理这一类视图：顶部、全宽、高度与导航区相同的底色、毛玻璃、顶部渐变图，以及导航区底边的细线。里面带按钮、标题、文字的视图一律不碰。清理时机：进入页面、每次周期复查、转场开始时（对即将进入的页面），以及页面滚动时（朋友圈滚动后才出现毛玻璃）。诊断里的 `runtime.pageTopPaintCleared` 记录清理次数。

## 聊天返回首页的原底栏

FIX28 的抓取显示：返回过程中，除了我们已经遮住的真实底栏背景以外，还有**第二块没被遮住、和底栏一样大的毛玻璃视图**（414×90，贴着屏幕底边，在标签页容器里，不在首页页面里），旁边还有一条底栏分隔线。它只在转场期间存在，所以“最后才消失”。FIX28 只认名字带 TabBar/Snapshot 的视图或图片，它两样都不是，所以一个都没找到（隐藏次数为 0）。

现在：
- 和底栏同尺寸、贴着底边的毛玻璃视图，以及底栏顶边的分隔线，都会被认出并隐藏；
- 查找会深入每个同级容器几层；
- 不碰正在离开的聊天页本身（它的输入栏）；
- 转场期间每一帧都查，新出现的视图下一帧就会被隐藏。

## 首页加号菜单的灰色原始背景

菜单背景是一张图片。之前只清掉了它这一帧的像素，但微信的加号菜单是复用的，每次打开都会重新设置图片；系统重新显示它时也会把像素画回来，所以“经常”跳出来。现在改为：
- 把图片本身换成同尺寸的透明图片，布局和大小不变；之后微信再设图片，也只会记下来、继续显示透明图片；恢复时放回微信最后设的那张。
- 每次系统提交画面之前，再检查一遍屏幕上菜单的原生底色，同一轮里微信设回去的底色，提交前就被清掉。

## 设置：材质遮盖分别控制

“材质遮盖 · 其余玻璃”和“材质遮盖 · 底栏”各自有“在边缘减弱”开关和“减弱范围”（0 = 不减弱）。上一版的独立分区已删除。首次运行沿用 FIX28 的效果。
