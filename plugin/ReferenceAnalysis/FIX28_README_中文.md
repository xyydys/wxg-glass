# WeChat Liquid Glass · TEST4 FIX28

版本 `0.4.28-test4fix28`，基于 FIX27。网格、几何、输入、底栏交互等 17 个源文件与 FIX27 逐字节相同（`tools/audit_fix28_scope.py`）。

## 聊天返回首页时的原底栏

视频号和其他页面已经解决，说明“隐藏微信转场用的底栏快照”这个思路是对的。聊天页的不同之处在时序：FIX27 在路由切换（也就是转场刚结束）时就把隐藏还原了。聊天页拆除更重，微信移除底栏快照比这晚一点，于是快照在这段空档里又露出来。

FIX28 的改法：
- 隐藏保持到**下一次转场开始**才还原；那时快照早已被移除，还原不会露出任何东西。
- 返回到标签首页的 pop 请求一发出（在 UIKit 开始转场之前）就开始查找并隐藏快照，不再只依赖系统转场回调。
- 查找范围从页面一直扩到窗口的每一层容器。
- 新诊断 `runtime.tabBarSnapshotLog`：每次隐藏了哪些视图、由什么触发（`popRequest` / `transitionToRoot`）、在哪个页面。如果聊天返回仍有底栏，请复现后导出，这一项会说明是没找到还是没触发。

## 首页加号菜单展开时闪一下灰底

可能的来源有两个，这版都处理了：
- **我们自己的占位色**：新建的玻璃在第一帧画好之前，会先显示一层材质底色作占位，深色模式下看起来就是灰色。同步模式下背景层一配置好就能渲染，所以现在不再显示占位色；玻璃在被激活的同一次布局里就挂好背景层、画好叠加层。
- **微信菜单自己的底色**：微信会先给菜单布局一次，然后才把按钮加进去。那时找不到菜单主体，原生底色就会先渲染出来。现在即使还没找到主体，也先清掉菜单的原生底色；并在主线程的下一轮重新查找（最多 6 次），按钮一出现就接上玻璃。

## 设置：材质遮盖 · 边缘减弱（独立分区）

- 新分区，对底栏和其余玻璃**同时生效**，只有一个“减弱范围”滑块。
- 0 = 不减弱，整块玻璃完全覆盖；大于 0 时，遮盖从轮廓开始在这个范围内由弱到强，范围以内完全覆盖。
- 原来的开关和两组里的“减弱范围”都已移除。首次运行沿用你原来的效果：原来关闭的为 0；原来开启的沿用 FIX27 的范围，若那里是 0 则取折射宽度。
- “材质遮盖 · 其余玻璃”和“材质遮盖 · 底栏”保留底色和深浅色遮盖程度。
