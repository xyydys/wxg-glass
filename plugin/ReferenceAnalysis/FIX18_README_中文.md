# WeChat Liquid Glass · TEST4 FIX18

版本 `0.4.18-test4fix18`，基于 FIX17。本版把三种渲染方式都做成可以**即时切换**的选项，方便在同一个画面上对比实际效果。

入口：设置 → 采样 → **渲染方式**（回读 / 混合 / 同步）。默认是“回读”。设置半屏打开时玻璃仍在刷新，可以边切换边看后面的效果。

## 三种方式

| | 回读 | 混合 | 同步 |
| --- | --- | --- | --- |
| 玻璃主体模糊 | 插件读取后 TEST9 高斯 | 系统渲染服务，上屏时计算 | 系统渲染服务 |
| 边缘折射 / RGB 色散 | TEST9 光学 | TEST9 光学（仅折射宽度内那一圈） | 无 |
| 透镜（底栏按压） | TEST9 完整光学 | TEST9 完整光学 | 系统渲染服务；背景不放大，图标仍放大 |
| 与内容同步 | 晚 1–3 帧，靠预测补偿 | 主体同步，边缘那圈有延迟 | 完全同步 |
| 主线程读取 | 有 | 有 | **没有** |

三种方式下材质遮盖、线框、选中胶囊、图标和按压动画都保留。

- **回读**：FIX17 的做法，光学着色器路径与 FIX17 逐字节一致（审计脚本把新增分支去掉后与 FIX17 着色器完全相同）。唯一改动是预测：减速段改按衰减估计，修正上一版“某一小段移动幅度变小”——那是直线推算在减速尾段提前到达终点造成的。
- **混合**：主体用私有 `CABackdropLayer`（系统毛玻璃背后的同一机制），由渲染服务在每帧上屏时取下面的像素并模糊，所以永远不拖。插件只在边缘折射宽度内输出 TEST9 折射和色散，向内平滑过渡到同步的主体。
- **同步**：主体和透镜都交给渲染服务，插件完全不读背景、不占主线程，只画材质遮盖、线框、选中胶囊和图标。代价是没有 TEST9 折射、RGB 色散和透镜背景放大，模糊覆盖扩展相当于 100%。

**同步模式模糊倍率**：把 TEST9 的模糊半径换算成系统高斯半径。我按“半径即标准差”设了 1.0，但两套高斯的定义未必一致；混合／同步的模糊看起来比回读强或弱时调它。

## 预测改进（回读、混合）

用三次采样估计速度变化：减速时按指数衰减外推，加速时保持直线（测试表明加入加速度项会在弹簧曲线速度峰值处冲过头，所以不用）。模拟 0.25–0.5 秒转场、16–48ms 延迟、60/120Hz：

| 曲线 | 平均误差 FIX17 → FIX18 | 减速尾段提前量 |
| --- | --- | --- |
| ease-out | 6.32 → 0.67 pt | 1.13 → 0.27 pt |
| ease-in-out | 12.65 → 10.13 pt | 4.54 → 1.09 pt |
| 弹簧 | 7.83 → 2.77 pt | 0.26 → 0.01 pt |

任何曲线的最坏情况都不比 FIX17 差；滚动的指数减速补偿误差小于 0.01pt。

## 安装

```bash
cd /var/mobile && unzip -o WeChatLiquidGlass_0_4_18_TEST4_FIX18_flat.zip -d WeChatLiquidGlass_FIX18 && cd WeChatLiquidGlass_FIX18 && chmod +x build.sh && ./build.sh rootless
```

rootful 环境把最后的参数换成 `rootful`。完全退出再打开微信，确认设置标题为 FIX18。

## 建议的对比方法

1. 带壁纸的聊天 → 聊天设置 → 返回，三种方式各看一遍，重点看拖影和果冻感。
2. 聊天页收放键盘、快速滚动后急停。
3. 首页底栏按住拖动透镜：回读和混合的透镜完全相同；同步模式的透镜背景不放大。
4. 同一页面对比三种方式的折射边缘观感，判断 TEST9 折射值不值得保留那一点延迟。

诊断字段：
- 每块玻璃 `materialLayers` 里有 `renderMode`、`bodyBackdropLive`、`bodyBackdropFiltered`、`bodyBackdropRadius`；
- `backdrop.renderMode` 与 `requestedRenderMode` 不同说明系统缺少 `CABackdropLayer`，已回退到回读；
- 同步模式下 `backdrop.regions` 应为空（不再读取）。

## 已知风险

- `CABackdropLayer`、`CAFilter` 是私有接口，我按 iOS 现有用法调用，**没有在 iOS 15.7 真机验证**。如果混合／同步模式里玻璃变成完全透明、没有模糊，请导出诊断看 `bodyBackdropLive` 和 `bodyBackdropFiltered`。
- 渲染服务看到的是屏幕上实际在玻璃下面的所有东西。回读模式会主动排除微信原生导航栏、输入栏等底层元素；同步模式不会。如果某处原生背景没有被插件清掉，它会出现在玻璃里。
- 透镜和主体共用一次捕获（同组），以免透镜里出现主体自己的图标。如果透镜伸出底栏的部分显示异常，也请截图。

## 验证边界

本环境没有 clang、iOS SDK 和 Metal 编译器：Objective-C 和着色器都未编译，以手机端 `./build.sh` 和首次运行时的着色器编译为准（失败会在诊断 `failure` 中显示）。已完成：35 个 C 测试（新增减速预测对比、同步合成公式）、全部源文件和着色器的括号结构检查、FIX17→FIX18 范围审计（含回读着色器路径一致性）。详见 `VALIDATION.md`。
