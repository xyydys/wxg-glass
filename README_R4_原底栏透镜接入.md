# R4：回到最初 FIX135，只接入按压透镜光学

安装包版本：`0.4.120-test4fix135v3r4`。包版本后缀沿用递增顺序以便覆盖 R3；源码基线是最初的 FIX135，不是继续叠加 V3/R1/R2/R3。

## 这次诊断确定了什么

诊断 13 的 R3 报告了 Apple Metal 编译错误：`float half` 使用了保留的标量类型名。它使玻璃管线 `ready=false`，两个 Metal 层隐藏，`presentedFrames=0`。因此只有独立的边框能运动。这个错误是 R3 引入的，不是手机性能不足，也不能据此判断参考项目的折射方案不可用。

此外，R2/R3 把主底栏自动改为 CPU 场景纹理取样，V2/V3 也改写了底栏本体光学；这超出了“保留已验证底栏和动效、替换按压透镜内部折射”的边界。R4 撤掉了这些变化。

## 基线和改动边界

原始提交：`a8686e190958812cfd8b3b25fb54e2c4afdd5ca0`。
参考：Kyant0/AndroidLiquidGlass，`eb4a0ea2e17542ea28c2e71088f7dd9acf77aad5`。

- 底栏本体：沿用最初的原生背景捕获、模糊、材质、折射及 iOS 26 边框。底栏 shader 原代码保留；没有新的 Kyant body 分支。
- 运动：保留原点击时序、跟手位置、速度形变和松手弹簧。`WXGDemoBar.m` 只新增一个主连续底栏标记，不改动画。
- 内收：重新使用原 FIX113 U/Y 的内收、与外层相接的渐变和形变补偿，不用 R3 的替代内收算法。新增的共享映射与原函数逐点对照。
- 按压透镜：参考项目的圆弧折射和七波长权重驱动原生背景网格；背景里看到的是现有底栏及页面。图标文字使用对应射线和同一内收映射。选中态按原逻辑退去。透镜沿用已有 iOS 26 边框实现，不增加参考项目描边。
- 原生背景使用已有的 Core Animation 捕获组。七层均保留有效 alpha，再通过原工程已有的 `plusL` 相加；不会再使用 V2 的零 alpha 色彩层。七波长只用于主透镜，不把底栏本体改成七层。
- `WXGEdgeFade.m`、`WXGBackdrop.m`、`WXGRim26.h`、`WXGOptics.h`、`WXGLensOptics.h` 均与原始源码一致。没有沿用 R1 的全局上下边缘修改。
- 移除 R1–R3 的底栏自动后端切换和 Kyant 本体设置。旧偏好可以继续保存在设备里，但 R4 不读取它们；原有设置不重置。

## 安装与对照

安装 deb 并重启微信，保留当前配置。

设置 → 底栏的“按压透镜 · Kyant R4”分组：

- 开启“透镜使用参考项目折射与色散”：主连续底栏在原来的系统实时模式下使用新透镜。需要原生网格折射开启。
- 关闭：使用原 FIX135 的透镜路径与配置中的边框选择。底栏本体在两种状态下都是原方案。
- 沿用此前保存的三个透镜参数：折射带宽、折射深度、色散；不擅自改成默认值。

先看底栏静止外观是否恢复，然后按住/滑过图标文字、连续点击、松手，比较镜内是否缩小、内容是否折射以及动效。此版本没有强制切换全局渲染模式；非系统实时模式使用原始路径。

## 编译失败保护与诊断

仍在原授权回调后编译内嵌着色器；没有跳过授权。若新 shader 在真机编译失败，记录错误并尝试编译随包保存的原 FIX135 shader，禁用新透镜，避免因新 shader 编译错误导致整套玻璃空白。若原 shader 或设备管线本身也失败，仍会报告错误，不能保证所有失败都可回退。

`shaderHasKyant` 现在只在新 shader 和三个管线创建成功后为真，不再只检查字符串标记。

主底栏诊断增加：

- `opticsBuild=FIX135_Kyant_Lens_R4`、`bodyPipeline=original_FIX135`。
- `referenceCompileError`：新 shader 编译失败的原因。
- `pressedOpticsHistory`：最近 24 条按压状态，包含透镜尺寸、内收、采样余量、带宽/深度、可见光谱层与已接受网格数量。松手后仍保留。

系统实时模式的 CPU `backdrop.captures` 可以保持 0，不能单独用它判断是否有背景。`accepted` 只表示网格被接受，不证明最终视觉已正确。

## 本地验证和实际限制

- 61 个 C 回归程序通过，包括新增 54,000 个内收映射对照点，与原函数的最大差值为 0。
- 84 组七波长网格构建成功，最高 4,422 顶点，低于原生构建器的 20,000 容量。
- CPU shader 对照：5,700 个采样点的底栏及关闭新透镜的输出与原始 shader 一致，三个原有后端的最大差值为 0。
- 稀疏图标/文字样本随折射与色散改变；6,693 个无内容的透镜覆盖层像素保持全透明。12 组按压/移动/松手状态没有非有限数值。
- C++ stand-in 新增 `half` 保留类型约束：能够拒绝旧 R3 的实际 shader；本版与原始回退 shader 均通过。
- iPhoneOS 16.5 SDK、arm64 iOS 14 目标、27 个 Objective-C 编译单元通过；签名、绑定、deb 权限与版本升级顺序检查通过。

这些是离线检查，不是 Apple Metal 编译和 iPhone 真机渲染验收。Core Animation 的光谱合成、实时观感和性能仍需真机测试。参考项目使用 Compose/Skia，本版是按当前工程架构移植对应光学，不能据此保证与参考演示逐像素相同。

`server/worker.js` 仅同步本地源码，没有部署。本次源码推送包含与 R4 对应的 Actions 检查：声明内嵌光学时验证新旧两个着色器，其余构建沿用原检查。完整日志和清单在 `plugin/Validation/repair_r4/`。
